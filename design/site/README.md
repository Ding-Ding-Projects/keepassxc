# Website design and implementation handoff

The existing website is being revised in its original repository and retains its established public address. The initial design prioritizes the published Windows download, factual release provenance, readable documentation, changelog access, and accessible navigation.

## Preferred design-tool attempt

Material Designer 0.21.519 was launched with a fresh isolated profile through the approved hidden-desktop route. Startup exposed both onboarding and a second desktop-pet renderer, preventing the required single-target isolation proof. Bounded background interaction did not complete onboarding. No design project or complete website handoff ZIP was exported. All owned processes and the desktop were closed.

The implementation therefore continues through the existing static website source and Sites workflow. This document is an implementation handoff, not a fabricated design-tool export or visual verification claim.

## First delivery slice

- Use locally bundled official Material Web controls for navigation and actions.
- Put the verified released version, local-time build provenance, and Windows x64 installer on the initial view.
- Separate Overview, Downloads, Documentation, Changelog, and Settings through keyboard-operable tabs.
- Keep private data and vocabulary out of published source, metadata, exports, and captures.
- State repair and verification gaps accurately. Never label source-only behavior as an installed-runtime result.
- Support narrow viewports and light/dark appearance. Further canonical feature completion remains governed by the per-surface inventory.

The running page and reference evidence must be captured after the build; source documents alone do not establish design parity or accessibility.
