# Native menu search

Every `QMenu` shown by the application is intercepted centrally after its
`aboutToShow` callbacks. `Material::MenuSearch` adds a local Material search row
and result status, including menus generated by Qt for text editors and
`Qt::ActionsContextMenu`. Existing Material search rows are reused.

## Behaviour

- Plain text is the default. Matching ignores case and mnemonic ampersands.
- Each menu owns its query, flags, mode, validation, full regular-expression
  workbench, sample and draft workbench state. No menu borrows the global
  workbench's draft. Existing preset snippets are supplied by `RegexBuilder`.
- The builder opens immediately below its search row inside the same popup.
  It never starts a separate top-level window or releases a stack-local
  `QMenu::exec()` caller. Closing the builder returns focus to its search row.
- Original actions are never cloned, reparented or reordered. Check state,
  enabled state, callbacks, submenus, shortcut text and ownership stay native.
- Hidden actions stay hidden. The controller restores filtering visibility
  when the popup closes or a shared action is removed. Queued updates from a
  closed popup cannot filter its shared actions again, even after reopening.
  Separators only appear between surviving groups.
- Typing filters; arrows explicitly choose an enabled result. Enter in the
  field does nothing. A query or flag edit clears the previous active action,
  so a hidden destructive command cannot survive as the Enter target.
- Escape closes the popup, returning focus to its opener when still valid.
- No-match, counts and validation use the voice catalogue in English,
  Cantonese and bilingual modes. Accessible status describes the result count.
- Existing Select popups keep their list keyboard behavior, including Enter
  selection and clear-first Escape. Their status counts the actual filtered
  choices, including changes while the popup is open. Flags-only edits reapply
  the existing search consumer without replacing its query.

## Bounds and privacy

Patterns are limited to 512 UTF-16 characters, labels to 2,048 characters and
filtered command sets to 1,024 entries. High-risk shapes are rejected. PCRE2
match/depth directives bound individual matches; an elapsed budget bounds the
whole filter. Invalid match results, including exhausted PCRE2 match limits,
discard all partial results and show the local resource-limit status.
Invalid or incomplete command searches expose no activatable result.
Only action labels are searched. No document field, credential or clipboard
content is read. Up to twenty query-history entries remain in memory with the
menu and are destroyed with it, never written to settings, logs or snapshots.

## Verification and limits

`testmaterialmenu` contains twenty-one focused cases, including its three
queued-update data rows, for installation, existing search reuse, isolation,
flags, Unicode, invalid patterns and match exhaustion, dynamic rebuilding,
native actions, Select keyboard/status behavior, shared-action restoration,
opener focus, editor menus and inline workbench lifetime.
Its process uses a temporary configuration and the Qt test namespace.

The handwritten route inventory is `design/context-menu-inventory.md`.
Source implementation is not a native rendering claim. Real packaged runtime,
screen-scale and keyboard/focus evidence must still be collected through the
approved hidden-desktop route. The embedded calendar's day grid is a custom
widget rather than command actions; its month/year pickers retain their own
searches, while day-grid filtering remains a separate implementation gap.
Arbitrary `QComboBox` popups are not `QMenu` and require their own adapter.
Per-element appearance and locks, custom saved snippets and a user-facing
query-history picker are outside this native-menu foundation.
